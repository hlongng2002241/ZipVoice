# FlowTTS-GRPO RL Post-Training for ZipVoice

- **Date:** 2026-08-28
- **Author:** LongNH (with Claude Code assistance)
- **Status:** Draft

## Goal

Add FlowTTS-GRPO-style online RL post-training to ZipVoice's flow-matching
decoder — converting deterministic ODE sampling to an SDE for GRPO exploration,
optimizing a weighted speaker-similarity/intelligibility/quality reward — gated
on a frozen front-end checkpoint and starting from LoRA/decoder-only tuning
rather than full-parameter fine-tuning from day one.

## Background

See [../../proposals/2026-08-28__flowtts_grpo_rl_finetuning.md](../../proposals/2026-08-28__flowtts_grpo_rl_finetuning.md)
and the sequencing/LoRA-first decision recorded in
[../../adr/2026-08-28__sequence_rl_after_frontend_freeze.md](../../adr/2026-08-28__sequence_rl_after_frontend_freeze.md).
Codex's review (gpt-5.6-sol, high reasoning effort, 2026-08-28) called the
original proposal "highest-risk/highest-reward... nowhere near ready for an
expensive training run" and identified concrete correctness gates, reward-hacking
risks, and a real (not just theoretical) dependency on the text front-end work in
[../2026-08-28__multilingual_tts_frontend/2026-08-28__overview.md](../2026-08-28__multilingual_tts_frontend/2026-08-28__overview.md).
All of Codex's recommendations were accepted.

## Scope

- **In scope:** SDE-rollout correctness validation for `EulerSolver`; batched,
  GPU-resident reward-function wrappers around the existing (and the user's
  Vietnamese-specific) evaluation models; the GRPO loss itself; a LoRA/decoder-only
  training run with reward-hacking monitoring and human evaluation; a
  full-parameter fine-tuning comparison as a follow-up ablation only.
- **Out of scope:** any change to the text front end (tokenizer, embedding,
  `[LANG:xx]` tokens) — that's the sibling plan's responsibility, and this plan
  must not start its training-run sprint until that plan's checkpoint is frozen.

## Risks & Open Questions

| Risk / Question | Impact | Mitigation / Owner |
| --- | --- | --- |
| Time-direction/sign match between ZipVoice and F5-TTS is necessary but not sufficient for the SDE formula to be correct | Silent training corruption that doesn't necessarily crash | Sprint 001's 7 correctness gates, run on synthetic tensors before any real training |
| Reward hacking (ASR-favorable-not-human-favorable acoustics, prompt-copying for speaker similarity, MOS-predictor exploitation, std-normalization amplifying near-zero-variance rewards) | RL optimizes proxy metrics at the expense of real quality | Supervised flow-matching replay/anchor loss alongside KL; mandatory human A/B evaluation before any rollout, not just proxy-reward trends |
| Existing offline eval models may not be batched/GPU-resident/fast enough to serve as reward functions | Reward orchestration becomes the bottleneck, or conflicts with rollout GPU memory | Sprint 001 explicitly budgets for adapting them, rather than assuming they're ready-made |
| Starting the training-run sprint before the front-end plan is actually frozen | Wastes RL compute on a checkpoint that gets invalidated | Sprint 002 has a hard, explicit blocking dependency — do not start early even if "close enough" |
| Hard-case (repetition) augmentation over-represented in training | Model learns unnatural repetition-heavy behavior | Separate, explicitly lower-weighted curriculum plus a dedicated normal-text regression suite |

## Testing & Validation

Sprint 001's 7 correctness gates (noise-scale limit, marginal-distribution
check, log-probability agreement, ratio sanity, KL sanity, CFG-off-still-conditional,
no-supervised-regression); sprint 002's dev-easy/dev-hard-style validation sets;
mandatory human A/B preference evaluation before considering any rollout.

## Rollout

An RL-tuned checkpoint is offered as an **opt-in alternative** inference
checkpoint pending human evaluation sign-off — it does not automatically replace
the supervised checkpoint from the front-end plan. Full-parameter fine-tuning is
only attempted as an explicitly-compared follow-up once the LoRA/decoder-only
version is shown stable, per the ADR.
